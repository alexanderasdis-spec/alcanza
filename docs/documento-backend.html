¿Qué es el backend de Alcanza?

Es una API REST hecha con Laravel 13. Recibe peticiones del frontend de React, valida los datos, aplica las reglas de negocio (por ejemplo, marcar una meta como cumplida) y guarda todo en una base de datos MySQL. Responde siempre en formato JSON.

Gracias al backend, las cuentas de usuario, el perfil, las metas y los abonos quedan guardados de forma permanente y no dependen del navegador. El código vive en una carpeta aparte del frontend, ~/alcanza-api, dentro de Ubuntu (WSL), y tiene su propio repositorio de Git.

Paso a paso: encender el backend

Esto es lo que se hace cada vez que se va a trabajar o a mostrar la app.

  1. Abrir una terminal de Ubuntu (en Windows: menú Inicio → "Ubuntu", o en VS Code una terminal WSL).
  2. Entrar a la carpeta del proyecto y levantar los contenedores: 
    cd ~/alcanza-api
./vendor/bin/sail up
    Se deja esa terminal abierta: ahí aparecen los mensajes de Laravel y MySQL.
  3. Comprobar que Laravel responde: abrir http://localhost/up en el navegador. Debe salir una página de "Application up".
  4. Comprobar la API: abrir http://localhost/api/perfil. Debe salir el perfil en JSON (o un 404 si todavía no se ha creado).
  5. Encender el frontend en otra terminal (en la carpeta de React): npm run dev, y abrir http://localhost:5173.
  6. Para apagar: Ctrl + C en la terminal de Sail, o desde otra terminal ./vendor/bin/sail stop. Los datos de MySQL no se borran al apagar.
¿Por qué sail up sin -d? Docker está instalado dentro de Ubuntu. Cuando no hay ningún programa usando WSL, Windows lo "duerme" y los contenedores se apagan solos. Dejar sail up corriendo en una terminal mantiene WSL despierto. Con sail up -d (en segundo plano) funciona, pero puede apagarse al rato.

Paso a paso: cómo se creó el proyecto

Estos pasos ya están hechos; quedan documentados para poder repetirlos en otro computador.

  1. Crear Laravel con Sail y MySQL. Normalmente se usa curl -s "https://laravel.build/alcanza-api?with=mysql" | bash, pero ese script termina pidiendo la contraseña de sudo. Se hizo lo mismo con un contenedor que trabaja con el usuario de Ubuntu, así no hace falta sudo: 
    docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp -e COMPOSER_HOME=/tmp/composer \
  -v "$HOME":/opt -w /opt laravelsail/php84-composer:latest \
  bash -c "laravel new alcanza-api --no-interaction && cd alcanza-api \
  && php ./artisan sail:install --with=mysql"
  2. Configurar el .env (el archivo de configuración, que no se sube a Git): 
    APP_NAME=Alcanza
DB_DATABASE=data_alcanza
VITE_PORT=5175                # libera el 5173 para React
FRONTEND_URLS=http://localhost:5173,http://localhost:5180
  3. Levantar los contenedores: ./vendor/bin/sail up -d. Solo hay dos: laravel.test (PHP) y mysql.
  4. Activar las rutas de API (igual que en el proyecto de clase): ./vendor/bin/sail artisan install:api. Crea routes/api.php e instala Sanctum. Se agregó el trait HasApiTokens al modelo User.
  5. Configurar CORS para que el navegador deje a React hablar con la API: ./vendor/bin/sail artisan config:publish cors y, en config/cors.php, permitir solo las direcciones de FRONTEND_URLS.
  6. Crear las migraciones, modelos, repositorios, servicios, Form Requests, controladores y rutas (secciones 7 a 11) y ejecutar ./vendor/bin/sail artisan migrate.
  7. Agregar Mailpit y el correo: servicio mailpit en compose.yaml, y en el .env MAIL_MAILER=smtp, MAIL_HOST=mailpit, MAIL_PORT=1025, APP_LOCALE=es y FRONTEND_URL (sección 11).
  8. Crear la colección de Postman en la carpeta postman/ y probarla con Newman (sección 14). Guardar cada avance con un commit de Git.
Errores en JSON: en bootstrap/app.php, Laravel 13 ya trae configurado que las rutas api/* respondan los errores (404, 422, 500) en JSON y no como página HTML.

Migraciones y modelos

Una migración describe cómo crear una tabla con código PHP. Así la base de datos se puede reconstruir en cualquier computador con sail artisan migrate. Las tres migraciones tienen fechas fijas en el nombre (2026_11_04_000001, …02, …03) para que se ejecuten en orden: primero perfiles, luego metas y al final abonos, porque cada una depende de la anterior.

// database/migrations/2026_11_04_000002_create_metas_table.php
Schema::create('metas', function (Blueprint $table) {
    $table->id();
    $table->foreignId('perfil_id')->constrained('perfiles')->cascadeOnDelete();
    $table->string('producto_id', 40);           // "78" o "ent-2" (catálogo del frontend)
    $table->decimal('precio', 14, 2);
    $table->unsignedTinyInteger('descuento')->default(0);
    $table->enum('estado', ['en_progreso', 'cumplida'])->default('en_progreso');
    // … nombre_producto, imagen, moneda, fecha_estimada y timestamps
});

El modelo Meta: columnas, relaciones y valores calculados

El modelo representa una fila de la tabla. Además de sus columnas, Meta entrega tres valores que no se guardan: se calculan cada vez con accessors y se agregan al JSON con $appends.

class Meta extends Model
{
    protected $table = 'metas';
    protected $fillable = ['perfil_id', 'producto_id', 'precio', 'descuento', 'estado', /* … */];
    protected $appends = ['precio_final', 'ahorrado', 'progreso'];

    public function abonos(): HasMany { return $this->hasMany(Abono::class); }

    // precio_final = precio con el descuento aplicado
    protected function precioFinal(): Attribute
    {
        return Attribute::get(fn () => round($this->precio * (1 - $this->descuento / 100), 2));
    }
    // ahorrado = suma de los abonos · progreso = ahorrado / precio_final × 100 (máximo 100)
}
  • $table en Perfil: Laravel adivinaría la tabla "perfils"; por eso se indica perfiles.
  • casts: convierte precio y monto a número, para que la API no los entregue como texto ("6500000.00").
  • $hidden: oculta el campo interno abonos_sum_monto, que ya se entrega como ahorrado.

Repositorios y servicios

RepositorioEs la única capa que habla con la base de datos. Usa Eloquent (Meta::create, ->update, ->delete). Cada uno tiene una interfaz en Contracts/ que dice qué métodos debe tener.
ServicioTiene las reglas de negocio: qué pasa cuando se crea una meta o llega un abono. No sabe de HTTP ni de SQL: recibe datos ya validados y usa el repositorio.

Paso clave: unir la interfaz con el repositorio

Los servicios piden la interfaz en su constructor, no la clase. En AppServiceProvider se le dice a Laravel qué clase entregar. Si mañana cambiara la forma de guardar los datos, solo se cambia esta línea:

// app/Providers/AppServiceProvider.php
public function register(): void
{
    $this->app->bind(PerfilRepositoryInterface::class, PerfilRepository::class);
    $this->app->bind(MetaRepositoryInterface::class, MetaRepository::class);
    $this->app->bind(AbonoRepositoryInterface::class, AbonoRepository::class);
}

La regla más importante: ¿la meta ya se cumplió?

// app/Services/MetaService.php
public function revisarEstado(Meta $meta): Meta
{
    $meta->loadSum('abonos', 'monto');   // suma los abonos en una sola consulta
    $estado = $meta->ahorrado >= $meta->precio_final ? Meta::CUMPLIDA : Meta::EN_PROGRESO;

    if ($meta->estado !== $estado) {
        $meta = $this->metaRepository->update($meta, ['estado' => $estado]);
    }
    return $meta;
}

Qué hace cada servicio

ServicioMétodos y reglas
AuthServiceregistrar(), iniciarSesion(), cerrarSesion(), enviarEnlace() y restablecer(): cuentas y tokens (sección 11).
PerfilServiceobtener(usuario) y guardar(usuario, datos): la primera vez crea el perfil del usuario y después lo actualiza. Devuelve si fue creado, para responder 201 o 200.

Validación con Form Requests

Cada Form Request tiene rules() con las reglas y messages() con los mensajes en español. Si algo no cumple, Laravel responde 422 automáticamente y el controlador nunca se ejecuta.

Form RequestReglas principales
PerfilRequestnombre: obligatorio, de 2 a 40 letras · ahorro_mensual: número mayor que 0 y hasta 100 millones. Son las mismas reglas que valida React.
MetaStoreRequestprecio > 0 · moneda en COP, USD o EUR · descuento de 0 a 100 · imagen debe ser una URL · fecha_estimada no puede ser pasada. El perfil no se envía: lo pone el servicio.
MetaUpdateRequestIgual, pero con sometimes: se envía solo lo que cambia. No permite cambiar el perfil, el producto ni el estado.
AbonoStoreRequestmonto > 0 · fecha opcional y no futura.

{ "message": "Escribe tu nombre. (and 1 more error)",
  "errors": { "nombre": ["Escribe tu nombre."],
              "ahorro_mensual": ["El ahorro debe ser mayor que cero."] } }

Cuentas de usuario y seguridad

Cada persona tiene su cuenta: se registra con nombre, correo y contraseña, inicia sesión y recibe un token de Sanctum. React envía ese token en cada petición (Authorization: Bearer <token>); sin él, las rutas protegidas responden 401.
MétodoRutaQué haceRespuestas
POST/api/registroCrea la cuenta y devuelve { usuario, token }201 · 422
POST/api/loginRevisa correo y contraseña y crea un token200 · 422 · 429
GET/api/usuarioUsuario dueño del token200 · 401
POST/api/logoutBorra el token actual204 · 401
POST/api/olvide-contrasenaEnvía el correo con el enlace200 · 422
POST/api/restablecer-contrasenaGuarda la contraseña nueva con el token del correo200 · 422

Siguen la misma arquitectura: AuthController → AuthService → UsuarioRepository, con los Form Requests RegistroRequest, LoginRequest, OlvideContrasenaRequest y RestablecerContrasenaRequest.

Solo el dueño toca su meta: MetaPolicy

// app/Policies/MetaPolicy.php — Laravel la encuentra sola por el nombre (Meta → MetaPolicy)
private function esDueno(User $usuario, Meta $meta): bool
{
    return $meta->perfil()->value('user_id') === $usuario->id;
}
// En el controlador: Gate::authorize('view', $meta);  → si no es el dueño, 403

Medidas de seguridad

  • Contraseñas: se guardan cifradas (cast hashed), nunca salen en el JSON y deben tener 8 caracteres, letras y números.
  • Sin pistas: login y "Olvidé mi contraseña" responden igual exista o no el correo.
  • Límite de intentos: RateLimiter::for('cuentas') permite 10 por minuto en cada ruta de cuenta (luego 429).
  • Recuperación: el enlace vence en 60 minutos y, al cambiar la contraseña, se borran todos los tokens del usuario.

El correo de "Olvidé mi contraseña"

En AppServiceProvider, ResetPassword::createUrlUsing hace que el enlace lleve a la página de React (FRONTEND_URL/restablecer?token=…&email=…) y ResetPassword::toMailUsing escribe el correo en español con el nombre del usuario. En desarrollo el correo no sale a internet: llega a Mailpit (http://localhost:8025).

Conexión con el frontend

  1. CORS: el navegador bloquea por defecto las peticiones de localhost:5173 a localhost, porque son "orígenes" distintos. config/cors.php le dice al navegador que la API acepta esas direcciones.
  2. Dirección de la API: React la lee de VITE_API_URL en su .env (http://localhost/api).
  3. Cliente Axios (src/services/api.js): envía siempre Accept: application/json y, con un interceptor, el token de la sesión. Si la API responde 401, borra el token y la app vuelve a "Iniciar sesión".
  4. Traducción de nombres: la API usa "snake_case" (ahorro_mensual, precio_final) y React "camelCase" (ahorroMensual, precioFinal). Los servicios perfilService.js y metasService.js traducen en los dos sentidos.
  5. Errores: un 422 se muestra junto al campo del formulario; si el backend está apagado, la app muestra "No pudimos conectar con el servidor" con el botón Reintentar.
// src/services/metasService.js (frontend) → POST /api/metas/{id}/abonos
const { data } = await api.post(`/metas/${metaId}/abonos`, { monto })
// data.meta.estado === 'cumplida'  →  la página lanza el confeti

Paso a paso: probar la API

Opción A · Con Postman (visual)

  1. Abrir Postman → Import → elegir los dos archivos de ~/alcanza-api/postman/ (desde Windows: \\wsl.localhost\Ubuntu-24.04\home\alex\alcanza-api\postman).
  2. Arriba a la derecha, elegir el entorno "alcanza-api local".
  3. Clic derecho en la colección → Run collection → Run. Las peticiones van en orden y cada una revisa su resultado. El token del login se guarda solo y se usa en las siguientes.

cd ~/alcanza-api
docker run --rm --network alcanza-api_sail -v "$PWD/postman":/etc/newman postman/newman:alpine \

Problemas comunes y soluciones

SíntomaCausa y solución
"Sail is not running"Los contenedores están apagados (WSL se durmió). Ejecutar ./vendor/bin/sail up en ~/alcanza-api.
La app dice "No pudimos conectar con el servidor"El backend está apagado. Encenderlo y tocar Reintentar.
El puerto 5173 está ocupadoEl Vite de Laravel lo usaba. Se resolvió con VITE_PORT=5175 en el .env del backend.
Newman: "connect ETIMEDOUT"Usar --network alcanza-api_sail y host=http://laravel.test, no host.docker.internal (lo bloquea el firewall de Windows).
Error de CORS en la consola del navegadorLa dirección del frontend no está en FRONTEND_URLS. Agregarla en el .env y ejecutar sail artisan config:clear.
Los errores salen en inglésAgregar el mensaje en messages() del Form Request (o en lang/es.json si es de una plantilla de Laravel).
401 "Unauthenticated."Falta el token o ya no sirve (cerró sesión o cambió la contraseña). Volver a iniciar sesión.
429 "Too Many Attempts"Se superaron 10 intentos por minuto en una ruta de cuenta. Esperar un minuto.
No llega el correo de recuperaciónRevisar que el contenedor mailpit esté encendido (sail ps) y abrir http://localhost:8025.
Error 500 al crear una metaRevisar los registros con ./vendor/bin/sail artisan pail o en storage/logs/laravel.log.
