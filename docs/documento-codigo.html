Visión general

Alcanza es una aplicación de una sola página (SPA) hecha con React 19 y Vite. El navegador descarga la app una vez y después React cambia de página sin recargar. Los productos vienen de DummyJSON, las tasas de cambio de ExchangeRate-API y, en la siguiente etapa, el perfil, las metas y los abonos se guardarán en una API propia en Laravel con MySQL.

El código está organizado en capas, y cada una tiene una sola responsabilidad. Las páginas nunca hablan directamente con una API ni con localStorage: siempre pasan por un hook y un servicio. Así, cambiar una fuente de datos (por ejemplo, DummyJSON por Mercado Libre, o localStorage por Laravel) solo toca un archivo.

Guardián de rutas: RequierePerfil

Es una ruta "padre" sin dirección propia. Si el perfil todavía se está consultando no pinta nada; si no existe, redirige a /bienvenida con <Navigate replace />; y si existe, pinta la ruta hija con <Outlet />. Usa useOutlet() para obtener la página actual y la envuelve en AnimatePresence con key={location.pathname}. Así la página que se va termina su animación de salida antes de que entre la nueva.

Estado global con Context API

Cada contexto se divide en tres archivos: el contexto (context/xContext.js), el proveedor (context/XProvider.jsx) y el hook para leerlo (hooks/useX.js). Se separan porque oxlint pide que un archivo de componentes solo exporte componentes, para que la recarga en vivo funcione bien.

TemauseTema() → { oscuro, alternarTema }
Pone o quita la clase dark en <html>. La primera vez sigue el tema del sistema operativo. Se guarda en localStorage.
PerfilusePerfil() → { perfil, cargando, guardarPerfil }
Carga el perfil al abrir la app con perfilService. cargando empieza en true para no redirigir antes de tiempo.
MonedauseMoneda() → { moneda, cambiarMoneda, tasas, convertir, formatear }
Guarda la moneda elegida y consulta las tasas una vez. formatear(valor, desde) convierte y da formato.

¿Por qué useCallback y useMemo en MonedaProvider?

Cada vez que un proveedor se vuelve a pintar, las funciones que crea son "nuevas" para React. Si formatear cambiara en cada render, los contadores animados que la reciben reiniciarían su conteo sin motivo. useCallback conserva la misma función mientras no cambien la moneda ni las tasas, y useMemo hace lo mismo con el objeto que comparte el contexto.

const formatear = useCallback(
  (valor, desde = 'USD') => {
    const convertido = convertir(valor, desde)
    // Sin tasas, el valor se muestra en su moneda original
    return convertido === null ? formatearMoneda(valor, desde) : formatearMoneda(convertido, moneda)
  },
  [convertir, moneda],
)

Hooks personalizados

Un hook personalizado es una función que empieza por use y usa otros hooks de React. Sirve para sacar lógica de los componentes y reutilizarla.

HookQué haceConcepto de React
useFetchConsulta datos asíncronos y entrega { datos, cargando, error, reintentar }. Ignora respuestas que llegan tarde.useState, useEffect, useMemo
useLocalStorageComo useState, pero guarda el valor en localStorage.useState perezoso, useEffect
useTemaLee y cambia el modo oscuro.useContext
usePerfilLee y guarda el perfil del usuario.useContext
useMonedaMoneda elegida, tasas, convertir y formatear.useContext
useAlcanceResponde "¿cuándo me lo compro?": meses y fecha para un precio.Hook que combina hooks
usePosicionMousePosición del mouse de -1 a 1, sin re-renderizar.useEffect + MotionValue
usePuedeAnimarMouseIndica si hay mouse y si el usuario acepta animaciones.matchMedia + useEffect

Cómo funciona useFetch por dentro

Recibe una función que devuelve una promesa (por ejemplo obtenerAntojos). Cada consulta recibe un "ticket" nuevo; la respuesta se guarda junto con el ticket que la pidió. Si el ticket guardado no es el de la consulta actual, la consulta actual sigue cargando. Así no se llama setState de forma síncrona dentro del efecto y nunca se muestra una respuesta vieja.

const consulta = useMemo(() => ({ cargar, intento }), [cargar, intento])

useEffect(() => {
  let vigente = true   // se apaga si el componente se desmonta
  consulta.cargar()
    .then((datos) => vigente && setRespuesta({ consulta, datos, error: null }))
    .catch((error) => vigente && setRespuesta({ consulta, datos: null, error }))
  return () => { vigente = false }
}, [consulta])

const cargando = respuesta.consulta !== consulta
Regla de uso: la función que se le pasa debe ser estable. Si depende de algo, se envuelve en useCallback: const cargar = useCallback(() => obtenerAntojo(id), [id]). Así solo se vuelve a consultar cuando cambia el id.

Servicios y APIs

Los servicios son la única parte del código que sabe de dónde vienen los datos. Todas sus funciones devuelven promesas, aunque el dato esté en el navegador: así se pueden reemplazar por peticiones a Laravel sin cambiar nada más.

ofertasServiceobtenerAntojos() · obtenerAntojo(id)
Junta los productos de la API con los propios de Entretenimiento. Guarda la promesa en caché: la API se consulta una vez por visita.
monedaServiceobtenerTasas()
Consulta open.er-api.com/v6/latest/USD y devuelve { USD, COP, EUR, actualizado }. También con caché.
perfilServiceobtenerPerfil() · guardarPerfil(p)
Temporal: usa localStorage. Cuando exista la API, por dentro usará Axios contra /api/perfil.

El adaptador de DummyJSON (services/fuentes/dummyjson.js)

Es el único archivo que conoce cómo responde DummyJSON. Pide la lista completa con limit=0 y solo los campos necesarios (select), traduce cada categoría de la API a una categoría de Alcanza y descarta las que no se usan (como groceries). Si un producto no existe (error 404) devuelve null en vez de fallar.

function adaptarProducto(producto) {
  const categoria = CATEGORIA_ALCANZA[producto.category]   // 'smartphones' → 'tecnologia'
  if (!categoria) return null
  return {
    id: String(producto.id), nombre: producto.title, marca: producto.brand ?? 'Sin marca',
    categoria, precio: producto.price,
    descuento: Math.round(producto.discountPercentage),
    imagen: producto.thumbnail, imagenes: producto.images ?? [producto.thumbnail],
    calificacion: producto.rating,
  }
}

Ejemplo completo: del catálogo a "¿cuándo me lo compro?"

Esto es lo que pasa, paso a paso, cuando el usuario entra a /antojos?categoria=tecnologia:

  1. React Router encuentra la ruta y pinta <Antojos /> dentro de RequierePerfil y LayoutPrincipal.
  2. Antojos llama useFetch(obtenerAntojos). Mientras cargando es true, muestra 8 tarjetas "fantasma" que laten.
  3. ofertasService revisa su caché; si está vacía, le pide los productos al adaptador de DummyJSON (Axios → GET /products?limit=0).
  4. El adaptador convierte cada producto al formato Antojo; el servicio le suma los 5 propios de Entretenimiento.
  5. Antojos lee la categoría y la búsqueda de la URL con useSearchParams y filtra con useMemo: el filtro se recalcula solo cuando cambian los productos o el texto buscado.
  6. Cada producto se pinta con TarjetaAntojo, que calcula el precio con descuento (precioConDescuento) y lo muestra con formatear() de useMoneda.
  7. useAlcance pasa ese precio a pesos con las tasas del día y lo divide entre el ahorro del perfil: mesesParaAlcanzar(precioCOP, ahorroMensual).
  8. Si el usuario cambia de moneda, solo cambia el contexto de moneda: React vuelve a pintar los precios, sin volver a consultar ninguna API.

Los cálculos (utils/calculos.js)

export function mesesParaAlcanzar(precio, ahorroMensual) {
  if (ahorroMensual <= 0) return Infinity
  // Siempre al menos 1 mes: aunque alcance de una vez, hay que ahorrarlo ese mes
  return Math.max(1, Math.ceil(precio / ahorroMensual))
}
// Ejemplo real: MacBook US$ 1.899,99 × 3.197,3 = $ 6.074.848 COP
//               6.074.848 ÷ 350.000 = 17,36  →  18 meses  →  mayo de 2028

Todas las funciones de utils/ son puras: con los mismos datos siempre devuelven lo mismo y no tocan el estado de React. Por eso se pueden probar y explicar por separado.

FunciónQué hace
precioConDescuentoprecio × (1 − descuento / 100), redondeado a dos decimales.
convertirMonedaPasa el valor a dólares y luego a la moneda destino: valor / tasas[desde] × tasas[hacia].
fechaEstimadaSuma los meses a hoy, fijando el día 1 para evitar saltos (31 de enero + 1 mes).
formatearMoneda / formatearMesUsan Intl en español de Colombia: $ 350.000, US$ 19,99, € 19,99, "mayo de 2028".
validarPerfilDevuelve un objeto con un mensaje por cada campo con error; vacío si todo está bien.

Formularios: el perfil rápido

FormularioPerfil es un formulario controlado: el valor de cada input vive en el estado datos, no en el DOM. Un solo manejador actualiza cualquier campo usando el atributo name:

const alCambiar = (evento) => {
  const { name, value } = evento.target
  const nuevosDatos = { ...datos, [name]: value }      // copia y reemplaza solo ese campo
  setDatos(nuevosDatos)
  // Después del primer intento de enviar, los errores se actualizan en vivo
  if (intentoEnviar) setErrores(validarPerfil(nuevosDatos))
}

Al enviar, evento.preventDefault() evita que el navegador recargue la página, se valida con validarPerfil y, si no hay errores, se llama guardarPerfil del contexto y se navega a Inicio con useNavigate. Los inputs usan aria-invalid y aria-describedby para que los lectores de pantalla anuncien el error.

Sistema de animaciones

Todas las animaciones comparten los ajustes de utils/animaciones.js (RESORTE_SUAVE, RESORTE_RAPIDO, CURVA_SALIDA, PASO_CASCADA), por eso se sienten como una sola familia.

ComponenteCómo funciona
FondoAnimadoCuatro luces con useTransform sobre la posición del mouse (parallax) y flotación infinita; un halo sigue al cursor.
TarjetaInteractivaCalcula la posición del cursor dentro de la tarjeta (0 a 1), la convierte en grados de inclinación y en un degradado con useMotionTemplate.
MagneticoMueve su contenido una fracción de la distancia entre el cursor y su centro, con un resorte.
AparecerwhileInView con viewport.once: aparece una sola vez al entrar en pantalla; orden crea la cascada.
ContadorAnimadoanimate(0, valor) escribe el número directo en el elemento (textContent) para no re-renderizar en cada cuadro.
FiltroCategorias / SelectorMonedaEl fondo del botón activo usa layoutId: Framer Motion lo desliza solo de un botón a otro.

Rendimiento y accesibilidad

  • La posición del mouse se guarda en MotionValue en vez de useState: se mueve decenas de veces por segundo sin volver a pintar React.
  • usePuedeAnimarMouse apaga los efectos de mouse en pantallas táctiles y con "reducir movimiento"; MotionConfig reducedMotion="user" hace lo mismo en todas las animaciones.
  • Las fotos del catálogo cargan con loading="lazy", y el catálogo y las tasas se consultan una sola vez por visita.

Documentación automática del código

Cada componente, hook, servicio y utilidad tiene un comentario JSDoc con su descripción, parámetros (@param), lo que devuelve (@returns) y un ejemplo (@example). TypeDoc lee esos comentarios y genera un sitio web navegable y con buscador, en español.

/**
 * Calcula cuántos meses de ahorro hacen falta para reunir un precio.
 * @param {number} precio - Lo que cuesta el antojo.
 * @param {number} ahorroMensual - Lo que el usuario ahorra cada mes.
 * @returns {number} Meses enteros necesarios.
 * @example mesesParaAlcanzar(1000000, 350000) // 3
 */

Se genera con npm run docs y queda en docs/codigo/index.html. La configuración está en typedoc.json (incluye la traducción al español de la interfaz) y tsconfig.docs.json, que solo sirve para que TypeDoc lea el JavaScript. ¿Por qué TypeDoc y no el generador JSDoc clásico? Porque el clásico no entiende tipos modernos como import('react').ReactNode o (valor: number) => string: dio 132 errores. TypeDoc lee los mismos comentarios sin problema.
